# Atlas encoding implementation — 2026-10-17

Status: candidate source and focused functional tests validated; performance acceptance pending. `encoder_workers=1` remains the default. No benchmark, GPU work, dependency installation or environment replacement was performed by the atlas worker.

`export_scene_glb(..., encoder_workers=2)` or `encoder_workers=4` opts into two or four encoder threads. Only 1, 2 and 4 are accepted. The FIFO contains at most the chosen worker count of pages, including running work. The caller writes each page's geometry, encoded image and material metadata in the original order before admitting another page. Page arrays become read-only when submitted; only existing bounded baker pages are retained, without copying the full scene. The PNG encoder and its palette, alpha, MEDIANCUT, dither and optimize parameters are unchanged.

A full raw atlas page is approximately 20 MiB for RGBA plus geometry/UV/indices. Thus the two/four-page queue bounds are roughly 40/80 MiB of raw page data; these are not total RSS bounds. Source arrays, baker workspace, Pillow quantization/encoding allocations, encoded PNGs and comparison captures consume additional memory. No eight-worker candidate or new default is introduced.

Producer, encoder and BIN writer failures propagate directly. Completed worker failures are checked before requesting more pages. On failure pending tasks are cancelled and running tasks are drained before the source assets and temporary BIN stream close. Final GLB creation retains the existing exclusive output and partial-file removal behavior. No alternate export path is attempted.

The existing `compact.elapsed_seconds` now explicitly means wall time in disjoint caller-thread geometry/image/final-write calls and encoding joins. `compact.encoding_join_seconds` means serial encoding duration with one worker, and FIFO result wait with two or four workers. `compact.main_thread_write_seconds` is the rest of that caller-thread compact interval. `compact.encoder_queue_pages` records the bound. `bake.elapsed_seconds` excludes those disjoint caller-thread intervals and includes bake wall time overlapped by workers. No overlapping worker duration is subtracted from bake time. The top-level complete-export wall timer remains authoritative for performance comparisons; the nested durations do not measure worker CPU or total PNG work.

Prepared tests reuse the existing bundle/baker fixtures and cover three pages/two workers and five pages/four workers with deliberately out-of-order completion, observed maximums of exactly two/four produced-unwritten pages, read-only worker input, caller-thread ordered writes, real palette and RGBA PNG encoding, complete GLB byte equality, invalid worker counts, failures during generation/encoding/geometry/image/final write, partial-output removal and an explicitly blocked running encoder that must drain before a writer exception returns.

Validation: AST parsing passed for `src/surfel_glb.py` and `test/test_surfel_glb.py` using the system Python 3.11 through `uv run --no-project`, with `UV_CACHE_DIR=/tmp/viewer-atlas-uv-cache` because the ordinary uv cache is read-only. The first syntax-check invocation failed to acquire that ordinary cache lock; it did not execute project code. After the independent Python 3.11 test environment was restored, the authorized focused `test/test_surfel_glb.py` run passed all 34 tests (pytest 4.43 s; outer wall 6.997 s; CPU 8.931 s; maximum child RSS 679,657,472 bytes; returncode 0). Original output and complete command/resource receipts are `atlas-tests.log` and `atlas-tests.json`; no retry or extra test run was needed. This is functional validation, not a performance experiment. Full fixed-input B1/C1/C2/B2 acceptance, page/texture/geometry association comparisons and an independent review are still required before considering a default change or a performance claim.
