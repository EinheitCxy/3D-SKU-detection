# 自动生成手工圈选口径的水平面积：设计草案

日期：2026-10-13。状态：Rick 已确认面积口径，并授权 subagents 实现。实现记录见 [计划](../plans/2026-10-13-manual-equivalent-footprint.md)，使用方式见 [货堆轮廓文档](../../manual_stack_outline.md)。真实人工参考与生产替换尚待验证。

## 已确认的目标

每一堆货物沿水平投影的外轮廓形成闭合 polygon，内部商品间的小空隙计入，明显的外部凹口保留；彼此分开的货堆分别计算后相加。自动结果应能在 Viewer 中叠加到人工圈选上检查。

公式为 `A = sum(area(stack_outline))`。堆之间的区域不能重复计入，错误重叠须先处理归组问题。人工圈选的语义是参考；人工标注本身仍受重建、显示及选点误差影响，不能代替现场尺寸真值。

原 `da3_self_exemplar_ground_footprint_union` 是逐 global ID 的 OBB 并集。已合并的修复使该算法更稳定，但其通过数量、排除覆盖率不能作为新目标的准确率。新结果必须使用不同的 metric 标识，不能以旧字段说明悄悄替换面积含义。

## 当前源码与可复用边界

以已合并的 `main` / `278bf22` 为后端设计基线；根工作区仍在 Viewer 分支，并有其他任务的未提交修改。实现位于独立工作树的 `feat/manual-equivalent-footprint` 分支。

| 位置 | 新方案中的用途 |
| --- | --- |
| `src/da3_footprint_stage.py::_masked_observations` | 复用已有 processed SAM masks 与三维点的对应关系，保留 frame/global ID 标签 |
| `utils/scene_orientation.py::get_scene_orientation` | 复用 Viewer 的共享水平方向 |
| `utils/ground_stack_footprint.py::estimate_frame_support_offsets` | 候选点的逐帧高度过滤；不将它当作轮廓恢复算法 |
| `utils/ground_stack_footprint.py::elevated_projected_points` | 当前同时做高度筛选和投影，需拆开职责后复用，不能直接沿精炼法向投影 |
| `modules/viewer_web/src/area-measurement.ts::polygonArea` | 人工 polygon 的面积与合法性规则；后端实现等价计算并做跨语言数值对照 |
| `modules/viewer_web/src/scene.ts` | 手工正交俯视坐标与候选自动轮廓叠加 |

人工 Viewer 用共享方向的 XZ 平面，现自动阶段还调用 `refine_support_normal`，二者不保证完全同向。新自动轮廓必须使用与人工标注相同的共享方向；精炼支撑面可用于高度/背景判断，不能暗中改变投影方向。使用同一份方向结果比较，避免导出时间不同引入方向差异。

候选二维坐标、平面原点/轴和对应 world-space 顶点必须可互相转换。Viewer 的居中平移不改变面积，但叠加显示必须应用一次正确的变换，不能把 viewer 坐标再次当 world 坐标旋转。

## 路线比较与建议

| 路线 | 优点 | 主要限制 | 本文建议 |
| --- | --- | --- | --- |
| 米制二维栅格、局部补缝、逐堆外轮廓 | 间隙和分辨率能用毫米解释；中间结果容易叠加检查 | 分辨率误差；补缝可能误连两堆或堵住 U 形入口 | 首个候选 |
| 逐堆 concave hull | 直接得到矢量凹轮廓 | 仍需先判断分堆；凹度参数和业务间隙宽度没有直接对应，稀疏边界可能被跨接 | 仅作有界对照，首候选失败后再决定是否实现 |
| 全场景 convex hull 或逐 ID OBB 并集 | 实现已有或简单 | 凸包填平外部凹口；OBB 保留逐商品矩形假设 | 不作为新目标的正式算法 |

SciPy 的 closing 是先膨胀后腐蚀，既能补小洞，也会改变细小凹口；因此不能把“做 closing”当成保留凹口的证明。[binary_closing 官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.binary_closing.html)

填孔根据空白是否连通到栅格外边界区分内外；保留下来的 U 形入口应继续连到外部。如果补缝先堵住入口，再填孔会把整块凹口吞掉，需专门检查这个失败模式。[binary_fill_holes 官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.binary_fill_holes.html)

Shapely 的 concave hull 提供 `ratio` 和 `allow_holes`，并不直接接收米制“最大可补间隙”。这是把它列为对照而非首选的工程判断。[concave_hull 官方说明](https://shapely.readthedocs.io/en/stable/reference/shapely.concave_hull.html)

## 首候选的数据流程

1. 从有效商品 mask 提取完整重建点，保留来源标签；global ID 用于解释来源，不作为每个矩形必须成功的门槛。不能只加载以前 OBB 成功的点，也不能把旧 Task 4 中已筛选的 component 快照当成完整输入。
2. 复用米制、有限坐标与支撑高度判断，将合格点投影到 Viewer 共享水平坐标。无法确定尺度或方向时仍不输出正式平方米结果。
3. 在米制二维栅格中表示投影证据。保留原始占据格与各帧贡献，避免多视角重复采样密度直接决定边界。稀疏单面不能仅凭一条线向外扩出假货堆。
4. 以有限补缝尺度生成候选分组和局部边界。分组不能完全依赖原始点的连通性，也不能依赖一个 global ID 属于同一堆；扫描到的窄缝和真实通道需要结合人工参考验证。
5. 对每个候选堆提取外轮廓。内部封闭小空隙按确认的口径计入，外部凹口保持外部连通；若算法把明显通道封成孔洞，判为候选失败。大面积封闭中庭是否计入尚未由本次对话覆盖，应单列实例审阅，不能自行推广“小空隙”的规则。
6. 输出逐堆 polygon、逐堆面积、总面积及叠加图。屏幕渲染出来的 Surfel 面片大小不参与几何面积计算。

补缝尺度是会影响业务语义的参数，不能从旧 D1 的 20 mm 外扩值直接继承；分堆也不能套用旧 D2 的“次大分量 20%”。两个真实货堆可有任意大小比例，不允许只保留最大堆。

最终结果来自轮廓 polygon；栅格面积只用于交叉检查。需要显式处理栅格边界 padding、对角连接、pixel centre/cell edge 和坐标原点。边界简化不得改变堆数、凹口连通性或引入自交。

## 参数与验证：先圈边界，再观察算法

目前只确认“小缝计入、明显凹口保留”，没有确认统一厘米阈值，也没有实际人工参考轮廓。不得宣称某个默认补缝半径已经满足目标。

建议先选两个开发场景由 Rick 确认人工边界；在同一水平坐标中记录希望连接的缝隙、希望保留的凹口及堆间通道。若这些宽度本身重叠，单一距离阈值无法表达口径，需要增加场景分组信息或显示人工复核，不能继续放大半径直至出面积。

首次实验可沿用 5 mm 作为候选栅格分辨率，并用 2.5 mm 作一次离散化敏感性检查。这只是复用现有 voxel 量级的起点，不代表毫米级精度。补缝半径候选由上述参考场景中实际标注的间隙确定；在观察保留场景结果前固定选择，不按每个测试场景单独调参。

| 最小验证案例 | 需要证明的行为 |
| --- | --- |
| 2×3 m 完整矩形及旋转版本 | 约 6 m²；坐标转换正确，离散误差可解释 |
| 外接 3×3 m、缺 2×2 m 角的 L 形 | 约 5 m²，不能变成 9 m² |
| U 形和逐渐变窄的开口 | 报告入口什么时候被错误闭合；明显凹口不能消失 |
| 一堆内部小缝与两个分离货堆 | 前者合为一堆；后者各自成轮廓，通道不计入 |
| 两堆大小悬殊 | 小堆不能因相对面积或点数小被直接丢弃 |
| 仅有一条正面投影、缺边、孤立噪声、稀疏局部 | 不臆造不可见进深；失败和歧义要能在叠加中识别 |
| 同坐标的前后端 polygon | Python 面积与 `polygonArea()` 一致；缩放/居中不改变结果 |

2026-10-13 已确认 fd4–fd8 的 NPZ、mapping 文件及 mask 目录存在；这是路径检查，不是新一轮算法验证。建议 fd4/fd5 作开发参考，fd6–fd8 保留验证。video1/video2 后续只有在完整输入可读时才纳入，不能把历史截图或删过的输入当作可复跑缓存。

对每个场景展示人工与自动边界、堆数、面积相对差、polygon IoU、双向边界距离分位数及错误合并/拆分。面积差小不能掩盖边界错位。人工边界由人确认，算法不能生成自己的参考答案；它检验的是圈选口径一致性，实际米制精度仍需要现场尺寸。

## 分阶段交付与输出变更

1. 建立同坐标的人工参考边界保存和叠加方式，只做验证必需的顶点导出/载入；不展开完整标注管理系统。
2. 以独立几何模块实现首候选，先通过上述合成案例，再读取已有缓存做场景对照；不运行重建模型、不下载权重。
3. 在 Viewer 展示自动与人工边界及逐堆/总面积，由实际轮廓决定是否采纳。遮挡缺边和帧间水平错位不会因更换面积公式消失。
4. 验证可用后再改正式入口、metric/schema、文档及直接相关测试；正式 `value_m2` 只能对应完整且明确的目标结果。候选/歧义轮廓可以保留供查看，不能冒充已接受面积，也不自动回退到 OBB。

原基于 per-ID OBB 的 D1 覆盖门及 mask/LOO 面积证据不能直接搬到新 estimator。若保留扰动检查，必须重新调用相同的整堆轮廓算法，不能一边用外轮廓正式值、一边用 OBB 值作验证。

数值验收阈值尚未承诺。当前授权实现前 3 阶段的独立候选与比较工具；实际人工参考验证通过后才决定正式入口替换。部署、push、重建 Docker 和帧间几何校正均不在本轮执行范围。
